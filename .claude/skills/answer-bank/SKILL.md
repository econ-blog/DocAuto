# 정답·족보 채우기

## 공통 원칙
- **추측 금지.** 근거 없으면 미등록으로 남긴다(`no_answer` / `incomplete_bank`가 정답).
- 값은 **정답 단일 문자열**. 표시줄(`※ 정답만 남기고…`)이 남아 있으면 미등록으로 취급된다.
- 반영은 지정 브랜치 커밋 → **확인 없이 바로 `main`에 merge·push** (사용자 상시 지시).

---

## 1. `no_answer` — 닥터빌 퀴즈

파일: `quiz_answers.json` = `{제품명: {문항텍스트: 정답보기텍스트}}`

1. 알림의 제품명으로 키를 찾는다. 스크립트가 미등록 문항의 값에 `[표시줄, 보기1, 보기2, …]` 리스트를 이미 깔아둔다(개수는 결과 JSON의 `bank_seeded`).
2. 정답 보기 텍스트만 남기고 표시줄과 나머지 보기를 지운다.
3. O/X도 화면 라벨 텍스트 그대로 저장한다.
4. 같은 제품의 구식 키가 `quiz_answers_legacy.json`에 남아 있으면 함께 삭제한다.

주의:
- 제품명 조회는 `normalize_product`(공백·구두점·대소문자 제거) 기준.
- **접미사가 다르면 다른 제품이다.** `아림시스` ≠ `아림시스주`, `시너지아` ≠ `시너지아정`. 합치지 않는다.
- 문항 하나라도 미매칭이면 제품 전체가 `no_answer`다.

---

## 2. `incomplete_bank` — 세미나 설문

알림의 각 `missing` 항목에 `bank` 값이 붙는다.

| `bank` | 파일 | 값 형식 |
|---|---|---|
| `quiz` | `survey_quiz_answers.json` | 보기 텍스트(권장) 또는 1-based 번호 |
| `text` | `survey_text_answers.json` | 입력할 문장 그대로 |
| `null` | — | 보기 2개 미만인 DOM 이상. 스크린샷을 본다 |

- 키는 스크립트가 이미 만들어 둔다. 값 자리의 표시줄+보기 중 정답만 남긴다.
- 주관식은 보기가 없으므로 빈 문자열이며, 빈 문자열은 항상 미등록이다.
- 복수 선택: `"1,3"` 또는 `["1","3"]`. 쉼표 분리는 모든 조각이 숫자일 때만 일어난다.
- 척도형 5점 = 매우 만족 / 만족 / 보통 / 불만족 / 매우 불만족.
- 번호는 위치 기반이라 세미나마다 보기 순서가 바뀌면 오답이 된다 — **텍스트로 적는 편이 안전하다.**
- 일반 선택형(`general`)은 항상 2번으로 자동 제출되므로 알림에 올라오지 않는다.

### 주관식 답변 톤
100~150자. 임상 경험은 있지만 설문에 성의 들일 여유는 없는 사람처럼.
구어체 반말 종결(`-임`/`-함`/`-음`), 문어체·격식체 금지, 미사여구·디테일 없이 짧고 무심하게.

## 3. 채팅으로 받은 정답

봇 인박스가 아니라 Claude에게 직접 준 지시다. `telegram_inbox.py`는 처리하지 않는다.

**A. `제품명 시퀀스`** (예: `징코샷 O24`)
1. `quiz_answers.json`에서 제품명을 찾는다(부분 일치 허용: 징코샷 → 대웅징코샷정240mg).
2. 그 제품에서 **리스트 값이 깔린 문항들**을 JSON 등장 순서대로 나열한다.
3. 시퀀스를 한 글자씩 매칭 — `o`/`O`/`x`/`X`는 해당 O/X 보기 텍스트, 숫자는 보기 리스트의 1-based 인덱스.
4. 각 값을 정답 텍스트 단일 문자열로 교체한다.

**B. `제품명 정답`** (예: `시너지아정 시트룰린`)
- 사용자가 짚어준 정답과 일치하는 보기만 남긴다(부분 일치 허용: 시트룰린 → `시트룰린 말산염 (Citrulline Malate)`).
- 문항이 여러 개면 문맥으로 판단하고, 애매하면 사용자에게 확인한다.

공통 마무리: `quiz_answers_legacy.json`의 같은 제품 구식 키 삭제 → 커밋 → `main` merge·push.

## 4. 오답 감지
`:text('오답입니다')` 감지 시 해당 키를 `quiz_answers.json`·`quiz_answers_legacy.json` **두 파일 모두에서** 삭제한다.
커밋 스텝이 두 파일을 함께 `git add` 해야 `git pull --rebase`가 미커밋 변경으로 exit 128 나지 않는다.
